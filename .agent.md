## 3. CORE ENGINEERING PRINCIPLES & PHILOSOPHY
This project is governed by strict architectural principles. Do not deviate from them.

### 3.1. Ordem de Prioridades Mandatória
Toda decisão deverá seguir estritamente esta ordem:
1. **Correção:** O PDF gerado é idêntico ao original? Renomeou certo? A regra funcionou?
2. **Robustez:** O sistema trava se um PDF for corrompido? A interface congela (deadlocks)?
3. **Simplicidade:** O código é compreensível?

### 3.2. Simplicidade (KISS) e YAGNI
A solução mais simples que satisfaça completamente os requisitos deverá ser preferida. Nunca aumente a complexidade apenas para tornar o código mais sofisticado. Se 3 linhas resolvem, não instale um pacote NuGet ou biblioteca externa de terceiros.

### 3.3. Proporcionalidade
O sistema tem em seu núcleo um motor C# focado em processamento batch de alta performance (Desktop Híbrido). Não trate o C# como um framework web pesado: evite padrões desnecessários (ex: `MediatR` ou Injeção de Dependência exagerada) caso não adicionem valor real e imediato ao processamento em lote.

### 3.4. Princípios Inquebráveis (Aplicar Continuamente)
A base de código deve, obrigatoriamente, refletir os seguintes atributos:
- **KISS** (Keep It Simple, Stupid)
- **YAGNI** (You Aren't Gonna Need It)
- **DRY** (Don't Repeat Yourself)
- **SRP** (Single Responsibility Principle)
- **Alta Coesão e Baixo Acoplamento**
- **Legibilidade e Código Previsível**
- **Responsabilidades Bem Definidas**

## 5. EXECUTION RULES FOR AI AGENTS
- **Zero Disk Temporaries (In-Memory Pipeline):** Do NOT create temporary `.tmp` or `.pdf` files on the user's hard drive just to extract text or perform OCR. Everything MUST be loaded and manipulated in RAM.

- **Sanitization Rule:** The workspace must remain clean. Delete any temporary scripts (`.js`, `.cjs`, `.sh`, `.py`) immediately after they serve their purpose.
- **Atomic Operations:** Write code $\rightarrow$ Compile $\rightarrow$ Test $\rightarrow$ Commit. 
- **Auto-Correção e Testes (Self-Healing Loop):** Após qualquer modificação, a IA é OBRIGADA a gerar testes exaustivos e realistas (C# xUnit/FluentAssertions, React Vitest). Se houver erro, a IA deve capturar os logs, analisar logicamente, corrigir e re-testar autonomamente. Nenhuma tarefa termina até a cobertura estar verde.
- **Zero Warning Policy:** Code is only acceptable if it passes build with ZERO errors and ZERO warnings.

- **Crash Safety:** You must account for memory leaks, out-of-memory (OOM) scenarios, and locked files (File in Use). Always use graceful degradation (e.g., if native OCR fails, fallback gracefully).

## 6. AUTONOMIA DE EXPANSÃO (SUBAGENTES E SKILLS EXTERNAS)
- **Criação de Subagentes:** A IA tem permissão total para criar e invocar novos subagentes altamente especializados de forma dinâmica (usando `define_subagent`) visando paralelizar radicalmente a execução do projeto.

## 7. AUTONOMIA ZERO-CLICK E USO DE FERRAMENTAS
Para evitar interrupções constantes solicitando autorização ao humano, a IA deve priorizar a autonomia operando dentro dos limites de segurança nativos do sistema.

1. **Prioridade Máxima para Ferramentas Nativas (Native API):**
   - Para **ler arquivos**, priorize a ferramenta `view_file`.
   - Para **buscar arquivos ou conteúdos**, priorize `find_by_name` e `grep_search`.
   - Para **criar arquivos**, priorize `write_to_file`.
   - Para **editar código**, priorize `replace_file_content` ou `multi_replace_file_content`.
   - **EXCEÇÃO CLARA:** O uso do terminal (via `run_command`) com comandos como `cat`, `grep`, `sed`, `awk` ou `echo` para manipulação direta de arquivos só é permitido se **NÃO HOUVER NENHUMA OUTRA MANEIRA** de realizar a atividade necessária através das ferramentas nativas (ex: limitações técnicas severas, operações de injeção em massa, etc).

2. **Diretrizes de Sandbox (Terminal Seguro):**
   - Quando rodar comandos no terminal (`run_command`), tente **sempre** usar a execução segura (`BypassSandbox: false`) primeiro. Isso permite que processos como scripts (`node`), compilações (`dotnet build`), linting ou testes rodem de forma autônoma sem travar esperando aprovação.
   - O uso do `BypassSandbox: true` (que exige intervenção e clique do humano) deve ser evitado ao máximo. Reserve-o unicamente para cenários que genuinamente necessitem de acesso à rede externa (ex: `npm install`, comandos `git` de push/pull) ou que exijam acesso de administrador global no SO.

3. **Artefatos e Rascunhos:**
   - Ao elaborar relatórios, painéis de decisão ou planos de implementação, faça o uso nativo do diretório de artefatos da memória do Agente, evitando "sujar" a árvore de arquivos de produção com documentos estáticos inúteis ao Build Final.
